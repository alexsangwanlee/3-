# tradebot: 업비트 자동매매 봇

업비트 원화마켓 현물 자동매매 봇입니다. 5년치 실제 데이터(4시간봉)에서 walk-forward 방식으로 전략과 파라미터를 고르고,
**API 키와 설정만 넣으면** 모의매매나 실거래로 24시간 돌아갑니다.

## 바로 실행하기

**0. 준비** (처음 한 번)

- Python 3.11 이상을 설치합니다: https://www.python.org/downloads/
  - Windows: 설치 첫 화면에서 **"Add python.exe to PATH"를 꼭 체크**하세요.
  - Mac: 기본으로 들어 있는 Python(3.9)은 안 됩니다. 위 링크에서 새로 설치하세요.
- 이 저장소를 받습니다. GitHub의 **Code → Download ZIP**으로 받아 압축을 풀거나, `git clone`을 씁니다.

**1. 제어판 열기**

- Windows: 폴더에서 `start.bat`을 더블클릭합니다.
- Mac/Linux: 터미널에서 그 폴더로 이동해(`cd 폴더경로`) `./start.sh`를 실행합니다. Mac에서는 `.sh`를 더블클릭해도 실행되지 않습니다.

처음에는 필요한 프로그램을 설치하느라 1~2분 걸리고, 브라우저에 제어판이 열립니다.
**모의매매 시작**을 누르면 실제 돈 없이 바로 돌아갑니다. 제어판 창을 닫아도 봇은 계속 돕니다.

**2. 실거래로 바꾸기** (모의매매 28일 후, 제어판의 "이번 주 점검"이 "Phase 1 진행 가능"이라고 할 때)

- 업비트 → 마이페이지 → Open API 관리에서 키를 발급합니다.
  - 권한은 **자산조회 · 주문조회 · 주문하기만** 켜세요. **출금 권한은 절대 켜지 마세요.**
  - 봇을 돌릴 PC·서버의 공인 IP를 등록하세요.
- 제어판의 **설정**에서 키를 붙여 넣고, 모드를 **실거래**로, 실거래 금액을 정한 뒤 저장합니다.
  키는 이 PC의 `.env` 파일에만 저장되고 화면에 다시 보이지 않습니다. 봇은 맡긴 금액만 굴리고 계좌의 다른 돈은 건드리지 않습니다.
- **연결 점검**을 누릅니다. 키·IP·주문 권한·잔고·텔레그램을 확인하고(실제 주문은 나가지 않습니다), 문제가 있으면 고치는 방법을 알려줍니다.
- (권장) 실제 주문까지 확인하려면 터미널에서 `./start.sh check --test-order`(Windows: `start.bat check --test-order`)를 실행합니다.
  봇이 쓰는 주문 경로 그대로 BTC 6,000원어치를 사고 바로 팔아, 주문·체결 확인·주문번호 재조회가 실제 업비트에서 되는지 봅니다.
  비용은 수수료 약 6원과 그 순간의 시세 차이입니다.
- "실제 돈으로 매매합니다"를 체크하고 **실거래 시작**을 누릅니다.

그다음은 [운영 계획](results/plan.md)대로 진행합니다. 제어판의 "이번 주 점검"(텔레그램으로도 매주 옵니다)이
지금 단계, 정상 범위 여부, 증액·출금 시점을 알려줍니다. 실거래는 잃어도 되는 금액으로만 하세요.

**24시간 서버에서 돌리기** (화면 없이)

```bash
./start.sh run                            # 모의매매. 실거래: ./start.sh run --i-understand-the-risk
```

Docker를 쓰면 꺼져도 자동으로 다시 켜집니다. 설정은 제어판에서 먼저 저장하거나 예제 파일을 복사해 편집하세요.

```bash
cp -n config.example.toml config.toml; cp -n .env.example .env   # 이미 있으면 덮어쓰지 않습니다
docker compose up -d && docker compose logs -f
```

- Docker는 mode와 상관없이 `--i-understand-the-risk`로 실행합니다. `config.toml`의 mode가 실거래면 바로 실거래입니다.
- 점검(FAIL)이 계속 반복되면 `docker compose down`으로 멈추고 설정을 고친 뒤 `docker compose up -d` 하세요.
  `.env`를 바꿨을 때도 `restart`가 아니라 `up -d`로 다시 띄워야 반영됩니다.
- 같은 폴더에서 Docker와 `start.sh`를 번갈아 쓰지 마세요. Docker가 만든 파일은 root 소유라 `start.sh`가 쓰지 못합니다.

## 수익을 지속시키는 계획 (요약)

| 단계 | 기간 | 돈 | 다음 단계 조건 |
|---|---|---|---|
| Phase 0 모의매매 | 28일 이상 | 0원 | 리포트 "정상 범위" |
| Phase 1 소액 실거래 | 90일 이상 | 목표 금액의 10~20% | 90일 "정상 범위" |
| Phase 2 증액 | 90일마다 | 최대 2배씩, 목표까지 | 직전 90일 "정상 범위" |
| Phase 3 유지 | 계속 | 목표 금액 | 분기마다 수익 30~50% 출금 |

- **목표: 수수료·슬리피지를 뺀 순수익 최대화.** 단 최대낙폭은 -30%보다 얕게 지킵니다(비상 정지 -35% 전에).
  과거 기준 기대치는 1년 중간값 +27%, 1년 손실 확률 8%, 최대낙폭 -10% 안팎입니다. 한 달 단위로는 절반이 손실이고, 그게 정상입니다.
- **지속성을 위한 구성:** 두 전략(donchian, ema_cross)에 예산을 반반 나눠 운용합니다.
  - 수익 분기가 42% → 63%로 늘었습니다.
  - 손실 연도(2022)는 -17% → -7%로 줄었습니다.
  - 1년 손실 확률은 21% → 15%로, 진입 확인 규칙을 더한 뒤 8%로 낮아졌습니다.
- **조정 규칙:** 손실 달에는 아무것도 바꾸지 않습니다. 리포트가 "점검 필요"라고 할 때만 모의매매로 돌리고 원인을 봅니다.
  전략 구성은 1년에 한 번 재검증할 때만 바꿉니다. 자세한 내용은 [`results/plan.md`](results/plan.md)에 있습니다.

## 목표: 하루 3%가 아니라 순수익 최대화

| 하루 수익률 | 30일 뒤 | 1년 뒤 |
|---|---|---|
| **3%** | 2.4배 | **48,483배** (1,000만원 → 4,848억원) |
| 1% | 1.35배 | 38배 |
| 0.073% (이 봇의 표본외 실적) | 1.02배 | 1.30배 |

- 세계 최고 수준의 퀀트 펀드(르네상스 메달리온)도 수수료 전 연 66% 안팎, 하루로 치면 약 0.14%입니다.
  하루 3%를 꾸준히 낸다고 홍보하는 봇이나 리딩방은 사기이거나, 고레버리지로 청산 직전까지 간 경우입니다.
- 업비트 5년치 실데이터(2021-10 ~ 2026-10, BTC/ETH/XRP/SOL/DOGE, 4시간봉)로 **학습에 쓰지 않은 기간만** 평가했습니다.
  현재 설정(두 전략 반반 + 진입 확인)은 **하루 평균 +0.073%, 연 +29.1%, 최대낙폭 -9.9%**였습니다.
  같은 기간 5개 코인 균등 보유는 +32.7%에 최대낙폭 -67%였습니다. 의미 있는 성과지만 하루 3%와는 41배 차이가 납니다.
- 그래서 목표를 **하루 목표 수익이 아니라 수수료 뺀 순수익 최대화**로 바꿨습니다. 하루 +3%에서 익절하고 멈추는 규칙은
  모든 전략에서 수익을 줄여서 뺐습니다([`results/guard_ablation.md`](results/guard_ablation.md)).
  수익을 더 내려고 위험을 2배로 늘리거나(1% → 2%) 파라미터를 수익 기준으로 고르는 방법도 시험했지만, 기간 절반에서 오히려 나빠져 넣지 않았습니다
  ([`results/edge_study.md`](results/edge_study.md)).

## 표본외(walk-forward) 결과

과거 180일로 파라미터를 고른 뒤 다음 60일을 그 파라미터로 매매하는 과정을 끝까지 반복했습니다.
60일 구간들을 이어 붙인 성과이므로 "미래를 모르는 상태에서 실제로 냈을 수익"에 가깝습니다.
수수료 0.05%와 슬리피지 0.05%(편도)를 반영했습니다. 기간은 2022-04 ~ 2026-10(1,646일)이고, 2022년 하락장을 포함합니다.

| 전략 | 누적 | 연환산 | 일평균 | 샤프 | 최대낙폭 | 거래 | 승률 |
|---|---|---|---|---|---|---|---|
| donchian (터틀 돌파) | +314.7% | +37.1% | +0.091% | 1.81 | -12.2% | 198 | 37% |
| ema_cross (이평 교차) | +118.1% | +18.9% | +0.051% | 1.16 | -12.3% | 113 | 19% |
| **현재 설정: donchian + ema_cross 반반** | **+216.4%** | **+29.1%** | **+0.073%** | **1.75** | **-9.9%** | 311 | 31% |
| vbo (변동성 돌파) | +34.8% | +6.8% | +0.020% | 0.68 | -15.9% | 1020 | 45% |
| rsi_mr (RSI-2 역추세) | -8.7% | -2.0% | -0.005% | -0.33 | -14.0% | 188 | 62% |
| 단순 보유 (5개 균등) | +32.7% | +6.5% | +0.061% | 0.39 | -66.8% | – | – |

봇은 매주 최근 180일 기준으로 각 전략의 파라미터를 다시 고르고 `state/selected.json`에 저장합니다.
[`results/selected.json`](results/selected.json)은 저장소에 함께 배포되는 시작값입니다.
현재는 donchian `{"n": 48, "m": 12, "stop_atr": 2}`, ema_cross `{"fast": 12, "slow": 120, "stop_atr": 3}`입니다.
모든 전략에 아래의 진입 확인(3 of 4)이 걸린 결과입니다(이전: 누적 +165%, 샤프 1.33, 최대낙폭 -16%).
승률은 31%뿐이지만, 손실은 작게 자르고 이익은 길게 가져가서 돈을 법니다.
donchian 단독이 더 높아 보이지만(+315%), 주간 자가 점검 기준(샤프 +0.15 이상)에 못 미쳐 두 전략 분산을 유지합니다.

## 수익 내고 손절 잘하는 법 (봇이 배운 규칙)

| 규칙 | 내용 | 근거 |
|---|---|---|
| 진입 | donchian: 48봉(8일) 최고가 돌파 / ema_cross: 12봉·120봉(2일·20일) 이평 골든크로스 | walk-forward가 매주 다시 고름 |
| **진입 확인 (확실한 타점)** | 아래 4개 중 **3개 이상**일 때만 삽니다: 코인이 200봉 이평 위 · BTC가 200봉 이평 위 · 최근 하루 거래량 ≥ 30일 평균 · 50봉 이평보다 3 ATR 넘게 오르지 않음(추격 매수 금지) | 샤프 1.44 → 1.80, 최대낙폭 -16% → -10%, 잠금 구간 +0.5% → +6.5%, 거래 수 478 → 311로 수수료도 줄임 ([`results/edge_study.md`](results/edge_study.md)) |
| 손절 | 진입가 - 2~3×ATR. 가격이 닿으면 10초 안에 시장가 매도 | 손실 1건당 장부의 최대 1% |
| 청산 | donchian: 12봉(2일) 최저가 이탈 / ema_cross: 데드크로스 | 추세가 꺾이면 나옴 |
| **수익 지키기** | 진입 후 +30% 이상 오르면, 최고가에서 -15% 떨어질 때 매도 | 2024-12-03 계엄 폭락 같은 날 큰 이익 반납을 막음 |
| 비중 | 예산을 두 전략에 반반, 각 장부 안에서 코인당 1/5씩. 변동성이 낮은 BTC에 많이, DOGE·SOL에 적게 | 최대낙폭 감소 |
| 하루 손실 한도 | 전략 장부가 하루 -5%면 그 전략만 청산하고 다음 날까지 중단 | |
| 비상 정지 | 전략 장부가 고점 대비 -35%면 그 전략만 청산 후 정지 | |

손절 규칙 4가지를 시험했고, 수익 지키기만 기준을 통과했습니다. 개발 구간 샤프가 1.15 → 1.35로 올랐고 최악의 날은 -10.5% → -6.0%였습니다.
다만 개선의 상당 부분이 2024-12-03 하루에서 나왔고, 규칙도 그날을 보고 설계했습니다. 그래서 **보험**으로 넣었습니다.
본전 손절, 12% 고정 손절, 손절폭 확대는 모두 효과가 없었습니다([`results/optimization.md`](results/optimization.md)).

## 예측과 변수: 이 봇은 어떻게 움직이나

전체 표와 행동 지침은 [`results/scenarios.md`](results/scenarios.md)에 있습니다. 재현은 `PYTHONPATH=. python scripts/scenarios.py`입니다.

**1,000만원으로 시작하면** (과거 표본외 수익을 1만 번 다시 뽑은 범위입니다):

| 기간 | 나쁜 경우 (하위 5%) | 중간값 | 좋은 경우 (상위 5%) | 손실 확률 |
|---|---|---|---|---|
| 1개월 | -3.3% | +0.0% | +16.7% | 47% |
| 3개월 | -5.2% | +3.8% | +29.7% | 31% |
| 1년 | -3.5% | +27.2% | +86.7% | 8% |

- **한 달 단위로는 절반이 손실입니다.** 수익은 강세장에 몰립니다: 강세장 하루 +0.19%(86%의 날에 포지션 보유), 횡보장 +0.04%.
  손실 달에 봇을 끄면 그 몇 달을 놓칩니다.
- **약세장에서는 거의 현금입니다.** 포지션을 든 날은 5%뿐이고, BTC가 하루 -0.15%일 때 봇은 -0.006%였습니다.
  BTC 최악의 10일 중 6일은 포지션이 없었고, 나머지 날의 최대 손실은 -2.1%였습니다.
- **변수의 영향:**

  | 변수 | 결과 |
  |---|---|
  | 기본 | +216%, 샤프 1.75 |
  | 수수료 2배 | +208%, 1.71 |
  | 슬리피지 4배 | +182%, 1.60 |
  | 주문이 4시간 늦게 | +251%, 1.84 (늦어도 나빠지지 않았지만, 손절은 늦으면 안 되니 **꺼지지 않는 PC·서버에서 돌리세요**) |
  | 4시간봉 기준 시각을 2시간 옮김 | (진입 확인 전 봇) +167% → +92%. 진입 확인 후에는 +124% |

- **언제 개입하나:**
  - 한 달 -3.3%까지는 정상 범위(20달에 1번)입니다. 끄지 마세요.
  - 낙폭이 -13.6%보다 깊어지면 리포트가 "점검 필요"라고 알립니다.
  - -35%면 봇이 스스로 멈춥니다.

## 최적의 방법 찾기: 팀 실험과 잠금 구간 검증

가설마다 하나씩 병렬로 검증했습니다. 2026-03까지의 개발 구간에서만 고르고, 마지막 6개월은 최종 후보에 대해 한 번만 열어봤습니다.
상세는 [`results/optimization.md`](results/optimization.md)에 있습니다.

| 가설 | 결과 (개발 구간 샤프) |
|---|---|
| 1시간봉 → **4시간봉** | ✅ 0.82 → 1.38, 최대낙폭 -27% → -15% |
| **변동성 역가중** | ✅ 최대낙폭 6~8%p 개선 |
| **수익 지키기** (+30% 후 -15%) | ✅ 1.15 → 1.35 (단, 대부분 하루의 효과) |
| 전략 분산 (donchian+ema) | ➖ 안정적이지만 새 수익원은 아님 |
| 트레일링 손절, 본전 손절, 고정 % 손절 | ❌ 큰 추세 수익을 잘라 악화 |
| BTC 200일선 위에서만 진입 | ❌ 상승 초입을 놓쳐 악화 |

잠금 구간 6개월(2026-04 ~ 10)에서는 개선이 확인되지 않았습니다. 시장은 +9%였지만 봇은 -1~-4%였고,
설정 간 차이는 통계적 잡음이었습니다. 추세추종은 횡보·완만한 상승장에서 약합니다.

## 워뇨띠 매매기록 학습

2026-09-22 공개된 워뇨띠의 비트멕스 체결 기록(2018-03 ~ 2021-12, 143만 건)을 학습해 봤습니다.
상세는 [`results/wonyotti.md`](results/wonyotti.md), 재현 스크립트는 `scripts/wonyotti_study.py`입니다.

- **포지션 복사:** 그의 포지션을 1시간 단위로 완벽히 복사해도 BTC 단순 보유(+302%)보다 못했습니다(롱만 +53%).
  수익은 1시간 안쪽의 체결 기술(지정가 리베이트, 스캘핑)에서 나왔습니다.
- **AI 모방 학습:** 2021년 검증 AUC가 0.40으로 동전 던지기보다 못했습니다. 2022~2026 업비트에서는 -34.7%였습니다.
- **가져온 것:** 매매 습관입니다. BTC·ETH 집중은 샤프가 높지만 수익이 줄어서 선택지로 남겼습니다.
  가장 쉽게 따라 할 습관은 **신고점마다 수익 일부를 출금**하는 것입니다.
- 공개 조건에 따라 **이 데이터로 만든 봇이나 상품은 판매하면 안 됩니다.** 원본 데이터는 저장소에 넣지 않았습니다.

## 스스로 배우고 고치는 부분

봇은 매주 스스로 다시 배웁니다. 다만 과거에 맞춰 잡음을 배우는 것(과최적화)이 자동매매에서 가장 흔한 실패라서,
**바꾸기 전에 반드시 "고르는 데 쓰지 않은 기간"에서 확인**하고, 전략 구성 변경은 사용자가 승인해야 적용됩니다.

| 무엇을 | 어떻게 | 언제 바뀌나 |
|---|---|---|
| 파라미터 | 데이터를 새로 받고 walk-forward로 각 전략의 파라미터를 다시 고릅니다 | 매주 자동. 그동안 매매는 계속합니다 |
| 전략 쉬기 | 최근 성과가 나빠진 전략은 새 매수를 멈추고 보유분만 관리합니다 | 매주 자동 |
| 실제 비용 | 실거래 체결가와 주문 시점 가격의 차이(슬리피지)를 기록합니다. 20건이 넘으면 그 중앙값으로 전략을 평가합니다 (가정보다 나쁠 때만) | 매주 자동 |
| 전략 구성 | 전략을 하나 더하거나 빼는 경우를 모두 채점합니다. 오래된 기간에서 샤프가 0.15 이상 높고 수익 분기 비율이 같거나 높으며, **최근 180일(고르는 데 안 쓴 기간)에서도 지지 않을 때만** 추천합니다 | 제어판에 "추천대로 전략 바꾸기" 버튼이 뜨고, 누를 때만 |

**시험했지만 넣지 않은 것: AI 진입 필터(메타 라벨링).** 과거 매매의 승패를 로지스틱 회귀로 학습해서, 질 것 같은 진입 30%를 건너뛰는 방식입니다.
미리 정한 세 기준(샤프 개선, 앞·뒤 절반 모두 개선, 예측력 AUC > 0.55)을 모두 통과하지 못해 기각했습니다.
샤프는 1.33 → 1.27로 떨어졌고 AUC는 0.545였습니다. 승률 15%인 ema_cross에서 +90% 거래 하나를 건너뛴 손해가,
작은 손실 여러 건을 피한 이득보다 컸습니다([`results/metalabel.md`](results/metalabel.md)).

## AI 연동 (Claude 또는 GPT): 매주 스스로 검토하고 안전한 조치는 직접 실행

제어판 **설정 → AI 주간 검토**에 Claude(console.anthropic.com) 또는 GPT(platform.openai.com) API 키 하나를 넣으면,
매주 재검증이 끝날 때 AI가 봇을 검토합니다. 둘 다 넣으면 Claude를 씁니다. 두 AI 모두 아래 규칙을 똑같이 따릅니다.
`./start.sh review`나 제어판의 **지금 검토 받기**로 언제든 받을 수도 있습니다.

- **AI가 보는 것:** 운영 계획 점검 결과, 최근 수익, 최근 거래 30건, 실제 슬리피지, 주간 자가 점검 결과, 오류 로그 요약,
  공포·탐욕 지수와 테더 프리미엄. 모두 봇이 만든 숫자이고, **API 키나 비밀값은 보내지 않습니다.**
- **AI가 하는 것:** 한국어로 요약하고, 위험 신호와 직접 확인할 것을 알려주고, 아래 조치 중 하나를 고릅니다.
  결과는 제어판과 텔레그램으로 옵니다.

| 조치 | 언제 고르나 | 자동 실행(설정에서 켰을 때) |
|---|---|---|
| 그대로 유지 | 기본값. 계획의 정상 범위 안이면 손실 달에도 이것 | – |
| 신규 매수 멈춤 | 점검 필요, 오류 반복, 슬리피지 이상, 장부 이상, 비상 정지 | ✅ 바로 실행 (보유분 손절·청산은 계속) |
| 검증된 전략 추천 적용 | 주간 자가 점검이 표본외 검증을 통과한 추천을 냈을 때만 | ✅ 바로 실행 |
| 신규 매수 다시 허용 | 멈춘 이유가 사라졌을 때 | ❌ 항상 직접 승인 |

**원칙: AI는 봇을 더 안전하게만 바꿀 수 있고, 위험을 늘리는 일은 사람이 정합니다.**
- 주문은 내지 않습니다. 손절은 10초 단위로 봇이 직접 합니다.
- 예산 증액, 레버리지, 리스크 한도는 제안하지 못하게 했습니다.
- 목록에 없는 조치나 검증되지 않은 전략은 무시됩니다.
- API가 실패해도 매매는 그대로 계속됩니다.

모델은 기본으로 Claude `claude-opus-5-5`, GPT `gpt-6-astra`(추론 강도 low)를 쓰고, 환경 변수 `CLAUDE_MODEL`·`OPENAI_MODEL`로 바꿀 수 있습니다.
검토는 주 1회이고, 지난 검토 뒤로 바뀐 것이 없으면 호출하지 않습니다. 이미 시험한 아이디어 목록(`results/knowledge.json`)을 함께 보내므로,
AI가 이미 결론 난 규칙을 다시 찾느라 토큰을 쓰지 않습니다.

## AI 매매: Claude와 GPT가 판단하고 서로 검토

제어판 **설정 → 전략**에서 `ai`를 고르면, 예산 한 몫을 AI가 직접 판단해 매매합니다. 규칙 전략 하나 이상과 함께 고르세요.

- **판단 시점:** 규칙 전략(donchian, ema_cross)에 매수 신호가 난 봉이거나, 코인을 들고 있을 때 하루 한 번(한국 시각 09시 봉)입니다.
  그 외에는 AI를 부르지 않아 토큰을 쓰지 않습니다.
- **서로 검토:** 한 AI가 코인마다 매수/매도/유지와 근거 규칙을 제안하면, 다른 AI가 검토합니다. 제안하는 쪽은 매번 번갈아 맡습니다.
  - 매수는 **둘 다 동의할 때만** 합니다.
  - 매도는 **한쪽만 원해도** 합니다. 위험을 줄이는 쪽이기 때문입니다.
  - AI 키가 하나뿐이면, 봇의 검증된 3-of-4 진입 확인 규칙이 두 번째 의견을 맡습니다.
- **공유 룰북:** 검증된 기본 규칙 5개에서 시작합니다.
  - 한 AI가 규칙을 더하거나 빼자고 하면, 다른 AI가 받아들일 때만 바뀝니다.
  - 규칙마다 실제 거래 성적(거래 수, 승, 손익)이 쌓이고, AI는 이 성적을 보고 규칙을 고칩니다.
  - 제어판에서 룰북과 최근 판단(누가 제안하고 누가 검토했는지, 토큰 수)을 볼 수 있습니다.
- **AI가 바꿀 수 없는 것(코드에서 강제):** 매수 수량(손절 시 장부의 1%), 손절가(진입가 - 2 ATR), 수익 지키기, 하루 손실 한도, 비상 정지, 그 전략 몫의 예산.
  API 키는 AI에 보내지 않습니다. AI 응답이 없으면 그 봉에는 새로 사지 않고, 손절은 그대로 작동합니다.
- **실거래는 모의매매 28일 뒤부터:** AI는 학습할 때 과거 가격을 이미 봤기 때문에, 과거 데이터로 AI 판단을 백테스트하면 미래를 아는 상태가 됩니다.
  그래서 실제 시간으로 돌린 모의매매 기록만 믿을 수 있습니다. 모의매매에서 AI가 실제로 판단한 날이 28일이 안 되면
  실거래 시작을 막습니다. 제어판에서 실거래와 ai를 함께 저장할 수도 없고, config.toml을 직접 고쳐도 봇은 ai 몫을 쓰지 않고
  나머지 전략만 돌립니다 (보유 코인의 손절은 계속).
  이 전략은 아직 검증되지 않았습니다. 제어판의 전략별 성과로 규칙 전략과 비교한 뒤 판단하세요.

## 비상 정지(-35%)를 풀려면

전략 장부가 고점 대비 -35%가 되면 그 전략은 전량 청산하고 새 매수를 멈춥니다. 다시 켜도 풀리지 않습니다.
원인을 확인한 뒤(시장 전체 폭락인지, 설정 실수인지) 봇을 정지하고 `./start.sh resume`(Windows: `start.bat resume`)을 실행하세요.
그 시점의 장부를 새 고점으로 삼아 다시 매매합니다.

## 명령어

`./start.sh 명령`(Windows: `start.bat 명령`)으로 실행하면 필요한 프로그램이 준비된 상태에서 돌아갑니다.

```bash
./start.sh                # 제어판 (브라우저)
./start.sh check          # 설정·키·주문 권한·알림 점검
./start.sh report         # 운영 계획 대비 현재 상태: 단계, 정상 범위 여부, 증액·출금 시점
./start.sh run            # 화면 없이 봇 실행 (모의/실거래는 config.toml 의 mode, 매주 자동 재최적화)
./start.sh resume         # 비상 정지(-35%) 해제
./start.sh review         # AI 검토 지금 받기 (Claude 또는 GPT API 키 필요)
./start.sh fetch          # 업비트 4시간봉 5년치 다운로드
./start.sh optimize       # 4개 전략 walk-forward + 자가 점검 → state/selected.json
./start.sh backtest --strategy donchian --params '{"n": 96, "m": 12, "stop_atr": 3}'
.venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest   # 테스트
```

## 한계 (꼭 읽어주세요)

- **과거 성과는 미래 수익을 보장하지 않습니다.** 진입 확인 규칙을 넣기 전에는 최근 6개월(잠금 구간)이 거의 제자리였습니다.
- **봉 기준 시각에 민감합니다.** 업비트 4시간봉(한국 시각 09·13·17시…)을 2시간 옮겨 다시 계산하면 수익이 크게 줄었습니다(+167% → +92%).
  진입 확인 규칙은 옮긴 시각에서도 개선(+124%)됐지만, 위 숫자는 가장 잘 맞는 시각 기준이라 실제는 더 낮을 수 있습니다.
- **생존 편향:** 지금 살아남은 대형 코인 5개로 검증했습니다. 상장폐지된 코인은 빠져 있습니다.
- **손절은 거래소 주문이 아닙니다.** 봇이 10초마다 가격을 보고 시장가로 팝니다. 급락 때 실제 체결가는 백테스트보다 나쁠 수 있고,
  봇이 꺼져 있으면 손절도 안 됩니다.
- 백테스트는 봉 안의 가격 순서를 모르기 때문에 보수적으로 가정했습니다(진입한 봉의 저가가 손절가 아래면 손절 처리).
- 봇은 `budget_krw` 장부만 봅니다. 계좌에 다른 원화가 있어도 되지만, 장부보다 실제 원화가 적어지면 그만큼만 매수합니다.
- 주문마다 고유 번호를 먼저 기록한 뒤 보냅니다. 응답이 끊기거나 봇이 꺼져도 다음 확인 때 업비트에 그 주문의 결과를 물어 장부에 반영하므로,
  같은 주문을 두 번 넣지 않습니다. 실제로 체결된 수량만 장부에 적습니다.
- 투자 판단과 손실의 책임은 사용자 본인에게 있습니다.

  - `ponytail`: 가장 단순한 해법 강제

  - `tdd` (mattpocock/skills)
  - `security-and-hardening` (addyosmani/agent-skills)
  - `frontend-design`, `web-design-guidelines`, `accessibility`: 제어판 디자인과 접근성 점검에 사용
