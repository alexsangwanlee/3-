# tradebot: 업비트 자동매매 봇

업비트 원화마켓 현물 자동매매 봇입니다. GitHub에서 널리 쓰이는 매매기법 4가지를 구현했고, 5년치 실제 데이터(4시간봉)에서
walk-forward 방식으로 전략과 파라미터를 고릅니다. 고른 전략은 모의매매(기본값)나 실거래로 24시간 돌릴 수 있습니다.

## 먼저 결론: 하루 3%는 불가능합니다

| 하루 수익률 | 30일 뒤 | 1년 뒤 |
|---|---|---|
| **3%** | 2.4배 | **48,483배** (1,000만원 → 4,848억원) |
| 1% | 1.35배 | 38배 |
| 0.061% (이 봇의 표본외 실적) | 1.02배 | 1.25배 |

- 세계 최고 수준의 퀀트 펀드(르네상스 메달리온)도 수수료 전 연 66% 안팎, 하루로 치면 약 0.14%입니다.
  하루 3%를 꾸준히 낸다고 홍보하는 봇이나 리딩방은 사기이거나, 고레버리지로 청산 직전까지 간 경우입니다.
- 업비트 5년치 실데이터(2021-10 ~ 2026-10, BTC/ETH/XRP/SOL/DOGE, 4시간봉)로 **학습에 쓰지 않은 기간만**
  평가했습니다. 가장 좋은 전략(Donchian 돌파)은 **하루 평균 +0.061%, 연 +22.1%, 최대낙폭 -18.4%**였습니다.
  같은 기간 5개 코인 단순 보유는 +38.7%(최대낙폭 -66%)였으니 의미 있는 성과지만, 하루 3%와는 49배 차이가 납니다.
- 49배 레버리지로 차이를 메우면, 검증 기간 최악의 날(-10.6%) 하루에 계좌의 5배가 넘는 손실이 나서 그날 바로 청산됩니다.
- 요청대로 **하루 +3% 도달 시 전량 익절하고 그날 매매를 멈추는 기능**을 넣었습니다. 다만 테스트해 보니
  **모든 전략에서 수익이 줄어서**(큰 추세일의 수익을 잘라냄) 기본값은 꺼져 있습니다. 근거는 [`results/guard_ablation.md`](results/guard_ablation.md)에 있습니다.

## 표본외(walk-forward) 결과

과거 180일로 파라미터를 고른 뒤 다음 60일을 그 파라미터로 매매하는 과정을 끝까지 반복했습니다.
60일 구간들을 이어 붙인 성과이므로 "미래를 모르는 상태에서 실제로 냈을 수익"에 가깝습니다.
수수료 0.05%와 슬리피지 0.05%(편도)를 반영했습니다. 기간은 2022-04 ~ 2026-10(1,646일)이고, 2022년 하락장을 포함합니다.

| 전략 | 누적 | 연환산 | 일평균 | 샤프 | 최대낙폭 | +3% 이상인 날 | 거래 | 승률 |
|---|---|---|---|---|---|---|---|---|
| **donchian** (터틀 돌파) | **+146.5%** | **+22.1%** | **+0.061%** | **1.04** | -18.4% | 1.9% | 324 | 28% |
| ema_cross (이평 교차) | +109.1% | +17.8% | +0.049% | 1.02 | -21.6% | 1.6% | 149 | 11% |
| vbo (변동성 돌파) | -22.4% | -5.5% | -0.013% | -0.40 | -29.7% | 0.7% | 1387 | 43% |
| rsi_mr (RSI-2 역추세) | -5.3% | -1.2% | -0.003% | -0.26 | -8.1% | 0.0% | 140 | 59% |
| 단순 보유 (5개 균등) | +38.7% | +7.5% | +0.063% | 0.41 | -66.3% | 10.7% | – | – |

`optimize`는 최근 180일 기준으로 **donchian `{"n": 96, "m": 12, "stop_atr": 3}`**를 골랐습니다([`results/selected.json`](results/selected.json)).
국내 GitHub에서 가장 유명한 변동성 돌파 전략은 수수료와 슬리피지를 넣고 표본외로 평가하면 손실이었습니다.

## 최적의 방법 찾기: 팀 실험과 잠금 구간 검증

5개 가설을 병렬로 검증했습니다. 2026-03까지의 개발 구간에서만 고르고, 마지막 6개월(2026-04 ~ 2026-10)은
최종 후보에 대해 딱 한 번만 열어봤습니다. 전체 표는 [`results/optimization.md`](results/optimization.md)에 있습니다.

| 가설 | 결과 (개발 구간 샤프, 기준 0.82) |
|---|---|
| 1시간봉 → **4시간봉** | ✅ 1.38, 앞뒤 절반 모두 개선, 최대낙폭 -27% → -15% |
| **변동성 역가중** (BTC 비중↑, DOGE·SOL 비중↓) | ✅ 0.91 (ema_cross 1.08 → 1.23), 최대낙폭 6~8%p 개선 |
| 전략 분산 (donchian+ema 반반) | ➖ 더 안정적이지만 새 수익원은 아님 |
| 트레일링 손절 | ❌ 큰 추세 수익을 잘라 오히려 악화 |
| BTC 200일선 위에서만 진입 | ❌ 상승 초입 진입을 막아 악화 |

**채택: 4시간봉 + 변동성 역가중** (개발 구간 샤프 0.82 → 1.17, 앞/뒤 절반 1.16 / 1.20, 최대낙폭 -26.8% → -18.4%).
잠금 구간 6개월에서는 개선이 확인되지 않았습니다. 기존 -0.7%, 새 설정 -3.7%로, 둘 다 시장 +9%를 놓쳤고 차이는 통계적 잡음(t=-0.93)입니다.
되돌리려면 `config.toml`에서 `timeframe = 60`, `vol_reweight = false`로 바꾸면 됩니다.

## 워뇨띠 매매기록 학습

2026-09-22 공개된 워뇨띠의 비트멕스 체결 기록(2018-03 ~ 2021-12, 143만 건)을 받아서 학습해 봤습니다.
상세는 [`results/wonyotti.md`](results/wonyotti.md), 재현 스크립트는 `scripts/wonyotti_study.py`입니다.

- **스타일:** 숏 비중이 높고(시간 기준 롱 21% / 숏 42%), 급락 뒤에 사고 급등 뒤에 파는 역추세였습니다.
  수익의 80%가 BTC·ETH에서 나왔고, 체결의 67%가 지정가(메이커)라 수수료가 오히려 수익이었습니다.
- **그대로 따라 하면:** 그의 포지션을 1시간 단위로 완벽히 복사해도 같은 기간 BTC 단순 보유(+302%)보다 못했습니다(롱만 +53%).
  수익은 1시간 안쪽의 체결 기술(메이커 리베이트, 스캘핑)에서 나왔습니다.
- **모방 학습(AI):** 학습 구간 AUC는 0.63이었지만, 2021년 검증에서 **0.40**으로 동전 던지기보다 못했습니다.
  2022~2026 업비트에서 그대로 매매하면 **-34.7%**입니다.
- **가져올 수 있는 것:** 매매 습관입니다. BTC·ETH 집중은 최악의 날을 -9.6%에서 -3.2%로 줄였지만 수익도 3분의 1 줄어서
  선택지로만 남겼습니다. 손실일 다음 날 비중 축소는 오히려 나빴습니다.
  가장 쉽게 따라 할 수 있는 습관은 **신고점마다 수익 일부를 출금하기**입니다(그는 수익의 80%를 출금했습니다).
- 본인도 서한에서 "매매봇이 실제 수익이 날 것 같을 경우 이미 자료가 있는 제가 먼저 만들어서 돌리고 있었을 것"이라고 썼습니다.
  공개 조건에 따라 **이 데이터로 만든 봇이나 상품은 판매하면 안 됩니다.** 원본 데이터는 저장소에 넣지 않았습니다.

## 구현 내용

| 기능 | 내용 | 참고한 공개 지식 |
|---|---|---|
| `vbo` | 시가 + k×전일 변동폭 돌파 시 매수, 다음날 시가에 매도. 노이즈 기반 k, 이동평균 필터, 변동성 조절 비중 | Larry Williams 변동성 돌파, pyupbit 예제 계열 |
| `donchian` | n봉 최고가 돌파 시 매수, m봉 최저가 이탈 시 매도 | 터틀 트레이딩 |
| `rsi_mr` | 상승추세(200이평 위)에서 RSI-2 과매도 시 매수, 반등 시 매도 | Larry Connors RSI-2 |
| `ema_cross` | 골든크로스 매수, 데드크로스 매도 | 고전 추세추종 |
| walk-forward | 학습/검증 구간을 굴려가며 표본외 성과만 평가하고 전략 자동 선택 | freqtrade hyperopt, vectorbt 등의 과최적화 방지 관행 |
| 같은 코드로 백테스트·실거래 | 전략은 봉 시가 기준 신호만 내고, 엔진/봇이 같은 규칙으로 체결 | jesse, freqtrade 구조 |
| 리스크 관리 | ATR 손절, 거래당 계좌 1% 리스크, 마켓당 1/N 배분 × 변동성 역가중, 일일 손실 한도 -5%, 최대낙폭 -35% 시 봇 정지, (선택) 일일 목표 +3% 익절 | 공통 관행, 리스크 패리티 |
| 미래참조 방지 | 각 봉의 신호가 그 봉의 고가/저가/종가에 의존하지 않음을 테스트로 검증 | |

현물만 거래합니다. 레버리지와 선물은 일부러 넣지 않았습니다.

## 빠른 시작

```bash
pip install -r requirements.txt
cp config.example.toml config.toml   # 설정 (주석 참고)

python -m tradebot fetch      # 업비트 4시간봉 5년치 다운로드 (data/, 최초 수 분)
python -m tradebot optimize   # 4개 전략 walk-forward → results/ 에 결과와 선택 전략 저장
python -m tradebot run        # 모의매매 시작 (실제 주문 없음, state/·logs/ 에 기록)

python -m tradebot backtest --strategy vbo --params '{"k": 0.5, "ma": 5}'   # 개별 백테스트
python -m pytest              # 테스트
```

`strategy = "auto"`이면 `optimize`가 고른 전략을 씁니다. 최근 성과가 마이너스인 전략만 남으면
봇은 **매매하지 않고 현금으로 대기**합니다.

## 실거래로 전환하기

1. 모의매매를 최소 2~4주 돌려 `logs/paper_trades.csv`를 확인합니다.
2. 업비트 → 마이페이지 → Open API 관리에서 키를 발급합니다. 권한은 **자산조회, 주문조회, 주문하기만** 켜고,
   **출금 권한은 절대 켜지 마세요.** 봇을 돌릴 서버의 IP를 등록합니다.
3. 키는 파일이 아니라 환경변수로 넣습니다.
   ```bash
   export UPBIT_ACCESS_KEY=...  UPBIT_SECRET_KEY=...
   ```
4. `config.toml`에서 `mode = "live"`로 바꾸고 실행합니다.
   ```bash
   python -m tradebot run --i-understand-the-risk
   ```
5. 운영 팁
   - 잃어도 되는 소액으로 시작하세요. 봇 전용 계정을 쓰는 게 좋습니다. 운영 중 원화를 입출금하면 일일 손익 계산이 틀어집니다.
   - 계속 켜두려면 `tmux`나 `systemd`로 실행하세요. 재시작해도 `state/live_state.json`에서 포지션과 리스크 상태를 이어받습니다.
   - 주 1회 정도 파라미터를 갱신하고 봇을 재시작합니다: `python -m tradebot fetch && python -m tradebot optimize` (cron 등록 권장).
   - 최대낙폭 한도에 걸려 봇이 정지하면, 원인을 확인한 뒤 `state/live_state.json`을 지워야 다시 매매합니다.

## 한계 (꼭 읽어주세요)

- **과거 성과는 미래 수익을 보장하지 않습니다.** 장세가 바뀌면 성과가 달라집니다.
- **생존 편향**: 지금 살아남은 대형 코인 5개로 검증했습니다. 상장폐지된 코인은 빠져 있습니다.
- **손절은 거래소 주문이 아닙니다.** 봇이 10초마다 가격을 보고 시장가로 팝니다. 급락 때 실제 체결가는
  백테스트보다 나쁠 수 있습니다.
- **손절선이 고정입니다(트레일링 아님).** 2024-12-03 같은 급락에는 큰 미실현 이익이 한 번에 사라질 수 있습니다.
  트레일링 손절도 시험했지만 수익을 크게 깎아서 넣지 않았습니다([`results/optimization.md`](results/optimization.md)).
- **최근 6개월(2026-04 ~ 10)은 손실이었습니다.** 시장은 +9%였지만 봇은 -3.7%였습니다. 추세추종은 횡보·완만한 상승장에서 약합니다.
- 백테스트는 봉 안의 가격 순서를 모르기 때문에 보수적으로 가정했습니다(진입한 봉의 저가가 손절가 아래면 손절 처리).
  일일 손익 한도도 봉 마감 기준으로 계산합니다.
- 투자 판단과 손실의 책임은 사용자 본인에게 있습니다.

## Claude Code 플러그인

`.claude/settings.json`에 플러그인 3개가 등록되어 있습니다. 이 저장소를 Claude Code로 열면 설치를 제안합니다.

- `andrej-karpathy-skills`: 코딩 원칙 4가지 (먼저 생각하기, 단순하게, 필요한 곳만 고치기, 검증 기준 정하기)
- `oh-my-claudecode`: 여러 에이전트가 나눠서 일하는 팀 모드 (`/oh-my-claudecode:team`). 매 프롬프트마다 Node 훅이 실행됩니다.
- `ponytail`: 가장 단순한 해법 강제 (YAGNI, 표준 라이브러리 우선)

`/skills`는 설치하는 게 아니라 사용 가능한 스킬 목록을 보여주는 Claude Code 기본 명령입니다.
